# Issue #57: 文書判断の受け入れケース

この文書は、固定された仮想入力を使い、統合後の手順が導く判断と根拠を人が照合するためのもの。実PR、watch、Council、scan、課金セッション、ブラウザー、実E2E、installedへの反映は行わない。手順の正本は [autonomous-dev](../SKILL.md) とそこから参照される各工程、機能対応は [coverage](../references/tstack-coverage.md)、共通の停止条件は [loop-engineering-core](../../loop-engineering-core/SKILL.md) と [development-flow](../../loop-engineering-core/references/development-flow.md)、実行工程は [loop-engineering-dev](../../loop-engineering-dev/SKILL.md) を参照する。ケースは工程の再定義ではなく、その工程で選ばれる結果の例である。

## 使い方と記録

- 仮想の `H0` と `H1` は異なるcommit、`B0` と `B1` は異なるbaseを表す。実在する名前・認証・PRに結び付けない。各ケースに書かれていない承認・証拠は存在しない。書かれた状態は観測済みという仮定であり、実サービスの観測結果ではない。
- 検証者は最終対象commitの全差分と参照先を読み、各入力から選ばれる行動・終了状態・理由が期待と一致するかを確認する。文言の一致だけで合格としない。別の適切な手順が期待の境界を守るなら根拠を記録して判断する。
- 各ケース末尾の **未実行** は作成時の初期値。実施結果の正本は Issue #57 の検証記録とし、このケース定義から合格を推測しない。ケース文の作成だけで合格としない。実施時はケースID、対象のfull SHA、dirtyがあれば追跡済み差分と未追跡ファイルの安全な識別子、日時・環境、読んだ箇所、観測した判断、根拠、合格／不合格／未検証と理由をprivateな記録に残す。結果の要約と安全な参照を担当へ渡す。秘密・個人情報・端末固有情報を公開記録へ転記しない。
- 固定SHA後に差分が変わったら、影響範囲を新しい版で再確認する。AC-T1の上流全件照合とAC-T5の独立Checkerは、個々の例が通るだけでは代替できない。
