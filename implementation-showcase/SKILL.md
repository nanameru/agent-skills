# 実装完了時の確認ページ

木村太陽さんのUI実装は、テキスト報告に加えて、実画面のスクショ・操作録画・説明をまとめたローカル確認ページを開いて完了報告する。

## 実施方法

- E2Eを伴う場合は `test-case-board/references/e2e-recording.md` に従って全実行の録画を保存する。この確認ページの短い紹介動画だけで、失敗・中断・再実行の記録を代用しない。ページには実行証跡を参照させ、未録画・保存未達も明示する。

- 対象の実装を起動して主要な利用操作を実際に確認する。変更が伝わる画面のスクショと、操作前→操作→結果が分かる短い録画を取得する。既存の利用可能なブラウザ／録画ツールを使い、記録した操作と検証範囲を残す。
- リポジトリに成果物保存ルールがあれば従う。なければ作業ディレクトリの `.artifacts/implementation-showcase/<作業名>/` を使う。認証情報や顧客情報が映らないテストデータを使う。
- [assets/index.html](assets/index.html) をそのディレクトリへコピーして内容を実装に合わせて編集する。サンプル文面はデモなので、実際の変更概要・確認手順・検証結果・未確認事項・Issue/PRリンクに置き換える。画像・動画は同じディレクトリ内の相対パスを使う。
- スクショには何を確認できるかの説明を付ける。動画は `controls`、`playsinline`、`preload="metadata"` を付け、無音で再生可能にする。自動再生しない。
- 証跡が取れなかった項目は、理由をその場に表示する。モック画像、静止画に動きを付けた映像、別バージョンの画面で検証を代用しない。スクショ連続撮影を動画化する場合は「画面キャプチャ記録（低フレームレート）」と明記し、通常の操作録画と区別する。
- 対象フォルダだけを loopback に配信する。例: `python3 -m http.server 41833 --bind 127.0.0.1 --directory <成果物ディレクトリ>`。空きポートを選び、既存サーバーを停止しない。作業ツールがプロセスを維持できる方式で起動する。
- ブラウザでそのURLを開き、画像の表示、動画の読込・再生、説明を実際に確認する。利用可能なら `open_in_codex` で確認ページを見せ、ユーザー向けのタブを残す。最終回答にURLと確認ページのスクショを添える。サーバーは確認できるよう残し、停止方法を成果物に記載する。

## 動く成果物そのものを見せる（T3 Code・Devin、本人の指定 2026-11-18）

本人の要望: 実装したら録画ではなく、その実装の成果物そのものを見せる。T3 CodeとDevinのどちらで見ても状態が分かるようにする。録画・E2E証跡のルールは別に守る（録画は省かない）。

**まず動くものを見せる。** 確認ページ（上の手順）は、動くものの横に置く説明と証跡の置き場として使う。

### T3 Codeで見せる（使えるツールで確かめた方法）

- Webの画面: 実装した開発サーバー（loopback）を起動したまま、`preview_open` の `target: {kind: "environment-port", port, path}` で右側のブラウザーペインに開き、変更した画面を表示したタブを本人向けに残す（AGENTS.md「ブラウザー」）。
- iOS / Android: `device_list` → `device_open` で本人のDevice panelにSimulator/Emulatorを出し、返された `agent-device` コマンドで実装したアプリを起動して変更した画面まで進めておく（AGENTS.md「iOS / Xcode・Simulator」）。
- 確認ページ・図・生成したHTML: `html_preview` で表示とconsoleを確かめてから `html_render` でスレッド内に出す。ローカル画像は絶対パスなら埋め込まれる。動画が再生できるかは `html_preview` の結果で確かめ、できなければ動画はURL・絶対パスで示す。
- 画像・ファイルの成果物: 最終回答にMarkdownの画像（絶対パス）や絶対パスのリンクで示す。
- 実行環境の上位指示がこれらのツールの使用を禁じる場面では、上位指示を優先し、使えなかったことと代わりの見方を報告に書く。

### Devinで見せる（確かめた範囲と未確認）

- 確かめたこと（2026-11-18）: T3からDevin Botへの[完了報告]は `~/.agents/bin/send-to-devin-bot` の1回のPOSTで、送れるのは `threadId`・`threadTitle`・`message` のテキストだけ（画像・ファイルの添付はない）。このMacのDevin CLIのセッション記録はこのMac上の作業フォルダを指している。
- 未確認: Devin Botの実行場所、Devin側でloopbackのURL・ローカル画像・HTMLを開いて表示できるか。確かめるまで「Devinに表示した」と書かない。
- そのため[完了報告]の本文に、次の「成果物の見方」を必ず入れる: ①何が動いているか（Webのポート・URL、Simulator名、生成ファイル）②開き方（URL、成果物と確認ページの絶対パス、起動・停止コマンド）③何を見れば変更が分かるか（画面と操作の手順）④Issue・PR・commit ⑤T3で実際に表示した場所 ⑥録画・E2E証跡の参照と状態（録画済み／録画不能／保存未達／非該当）⑦未確認・見られない場所とその理由。secret・会話全文・セッションIDは書かない。端末固有のパスはGitHubに書かない（Devin Botへの報告本文には書いてよい）。
- Devin自身（このMacのDevin CLIなど）が実装したときは、Devinの画面で使えるブラウザー等で成果物を開けた場合だけ「Devinで表示した」と書く。T3側にも見せる必要があるときは、上の「成果物の見方」を報告に入れ、T3側の表示は親（T3）またはT3の子が行う。
- Devin側で見られる場所（PRのプレビュー環境など）を新たに公開・デプロイしない。既にある承認済みの場所だけを案内する。

## 適用範囲

通常のコーディング依頼をこの手順で締める。質問・調査だけの依頼や、ユーザーが短い回答を求めたときには作らない。UIがない変更では、実コマンドの結果と説明を載せ、画面撮影・録画は対象外と明記する。未実装のデモを実装完了として扱わない。

iOSのビルド・Simulator・画面撮影は、AGENTS.md「iOS / Xcode・Simulator」とリポジトリのAGENTS.md（ローカル実行を禁じるリポジトリはそちらに従い、Devin macOSの結果・スクショ・録画を受け取って組み込む）に従う。録画手段がなければ、その制約を明示して利用可能な証跡を提示する。

Issue、テスト、コミットなどは作業先の規約に従う。このスキルはマージ・デプロイ・公開の許可を追加しない。
