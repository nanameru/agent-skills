# 実装完了時の確認ページ

木村太陽さんのUI実装は、テキスト報告に加えて、実画面のスクショ・操作録画・説明をまとめたローカル確認ページを開いて完了報告する。

## 実施方法

- 対象の実装を起動して主要な利用操作を実際に確認する。変更が伝わる画面のスクショと、操作前→操作→結果が分かる短い録画を取得する。既存の利用可能なブラウザ／録画ツールを使い、記録した操作と検証範囲を残す。
- リポジトリに成果物保存ルールがあれば従う。なければ作業ディレクトリの `.artifacts/implementation-showcase/<作業名>/` を使う。認証情報や顧客情報が映らないテストデータを使う。
- [assets/index.html](assets/index.html) をそのディレクトリへコピーして内容を実装に合わせて編集する。サンプル文面はデモなので、実際の変更概要・確認手順・検証結果・未確認事項・Issue/PRリンクに置き換える。画像・動画は同じディレクトリ内の相対パスを使う。
- スクショには何を確認できるかの説明を付ける。動画は `controls`、`playsinline`、`preload="metadata"` を付け、無音で再生可能にする。自動再生しない。
- 証跡が取れなかった項目は、理由をその場に表示する。モック画像、静止画に動きを付けた映像、別バージョンの画面で検証を代用しない。スクショ連続撮影を動画化する場合は「画面キャプチャ記録（低フレームレート）」と明記し、通常の操作録画と区別する。
- 対象フォルダだけを loopback に配信する。例: `python3 -m http.server 41833 --bind 127.0.0.1 --directory <成果物ディレクトリ>`。空きポートを選び、既存サーバーを停止しない。作業ツールがプロセスを維持できる方式で起動する。
- ブラウザでそのURLを開き、画像の表示、動画の読込・再生、説明を実際に確認する。利用可能なら `open_in_codex` で確認ページを見せ、ユーザー向けのタブを残す。最終回答にURLと確認ページのスクショを添える。サーバーは確認できるよう残し、停止方法を成果物に記載する。

## 適用範囲

通常のコーディング依頼をこの手順で締める。質問・調査だけの依頼や、ユーザーが短い回答を求めたときには作らない。UIがない変更では、実コマンドの結果と説明を載せ、画面撮影・録画は対象外と明記する。未実装のデモを実装完了として扱わない。

iOSではこのMacの `xcodebuild`、Simulator起動、画面撮影を行わず、Devin macOSの検証結果・スクショ・録画を受け取って組み込む。録画手段がなければ、その制約を明示して利用可能な証跡を提示する。

Issue、テスト、コミットなどは作業先の規約に従う。このスキルはマージ・デプロイ・公開の許可を追加しない。
