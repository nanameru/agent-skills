# Zoom Source Handling

`note-pro-publish` における Zoom録画・Zoom由来素材の扱いの正本。`note-parent-prompt.md` から参照される。親プロンプトと矛盾する場合は、Zoom素材の扱いに関してはこのファイルを正とし、それ以外は親プロンプトを正とする。

## 主ソースの優先順位

1. `zoom-lecture-publish` スキルが作成したハンドオフバンドル（`note-drafts/handoffs/*.json`）。transcript / chat / summary / サムネ / スクショ / 共有リンクのパスが揃っているので、ゼロから探し直さない。
2. VTT文字起こし（発言内容・タイムスタンプの一次ソース）。
3. Zoomチャット（共有リンク・参加者の質問・補足の一次ソース）。
4. 録画映像そのもの（スクリーンショット採取と、VTTで曖昧な箇所の確認用）。
5. 講義 summary / 既存メモ（構成の参考。事実の根拠としては VTT を優先）。

ハンドオフバンドルがない場合は、ユーザーに録画・VTT・チャットの場所を確認するか、`zoom-lecture-publish` の「Zoom録画→note記事だけ分岐」を先に実行する。

## VTT / transcript の扱い

- 発言の引用・要約は VTT を根拠にする。記憶や推測で発言内容を作らない。
- ただし記事は文字起こしの要約ではない。書き手本人の意見・判断・実験ログとして再構成する（親プロンプトの文章方針に従う）。
- `講義でも言ったように`、`今回の講義`、`講義中に共有された` のような講義レキャップ表現は使わない。
- VTTの誤認識（固有名詞・コマンド名・URL）は、一次情報（公式ドキュメント・GitHub・製品ページ）で必ず確認してから本文に書く。

## Zoom chat / コメント欄の扱い

- チャットで共有されたリンクは、記事の参考資料候補として全件ソースメモに残す（URL・共有者・文脈）。
- チャット内の質問は「読者がつまずくポイント」の一次情報として扱い、`つまずきやすいところ` 節の材料にする。
- 参加者の発言・質問を本文に使う場合は、個人が特定できない形に匿名化する。@handle・氏名・アイコンは出さない。
- チャットでXポストが言及されていた場合のみ、X検索での裏取りを検討する（SKILL.md の条件に従う）。

## 録画スクリーンショットの扱い

親プロンプトのスクリーンショット方針に加えて:

- 顔中心の画面より、関連するUIや画面共有を優先する。
- Zoom参加者一覧、Webカメラの顔、無関係な黒帯、読めないUIは必ず切り取る。
- スクリーンショットは VTT のタイムスタンプ周辺から候補を複数取り、直後の本文段落と内容が一致するものだけを採用する。
- 近くの文章を直接支えないスクリーンショットは、HTML/CSS図解に置き換えるか削除する。
- 画面内に映り込んだ氏名・メールアドレス・APIキー・トークン・社外秘情報は、切り取りかマスクで除去してからアップロードする。

## 録画由来の実装素材（コード・コマンド・設定）の扱い

- 録画内で実演されたコマンド・コードは、そのまま書き起こさず、自分で動作確認するか一次情報と突き合わせてから本文に載せる。
- 録画時点と現在でバージョン・仕様が変わっている可能性を常に疑い、変わりうる事実はWeb検索・公式ドキュメントで再確認する。録画の手順と公式の推奨が違う場合は、その区別を明記する（例: `公式の推奨インストールはAだが、この記事では検証用にBのルートも扱う`）。
- 実装の詳細（コマンド、プロンプト、チェックリスト、失敗パターン、運用注意）は有料区切りの後ろに置く（Pro記事の本文構成は `article-structure.md` に従う）。

## LMS連携

- 講義が PORSEO LMS / AI PLAY GUILD に公開済みの場合、LMS URL（`https://aiplayguild.com/videos/<videoId>`）は「メンバー向けハンズオン」として自然な Markdown リンクで紹介する。生URLを貼らない。
- 最初のハンズオンリンクの直前にはサムネイル画像を置く（親プロンプトのリンク方針に従う）。
- LMSに公開しない「note記事だけ」分岐の場合は、LMSリンクを発明しない。

## 禁止事項

- ハンドオフバンドル・ソースメモ・コミット・最終報告に、Zoomの録画URLトークン、preview アクセストークン、cookie、APIキーを書かない。
- 未検証の講義（Convex未公開・Mux未ready等）から記事を作らない。ユーザーが明示的に「不完全な素材からドラフトを」と頼んだ場合のみ例外。
- Zoom以外の素材しかない記事をこのスキルで作らない。その場合は `note-free-publish` / `note-light-publish` に切り替える。
