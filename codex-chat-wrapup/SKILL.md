# Codex Chat Wrapup

ユーザーは、実作業・判断・タスク状態の変化があったターンの終了時に現在チャットを改名・振り分けすることを許可している。対象ターンの最終回答直前に1回だけ実行する。途中の進捗更新では実行しない。ユーザーの明示的な「名前や配置を変えない」指定を優先する。

## ツールを呼ぶ前の省略判定

- 挨拶・お礼・短い相づちだけで、タスクの状態・次の行動が変わらない場合は整理しない。共通AGENTSでもこの判定をスキル読込前に行い、スキル読込・環境照会・一覧取得・改名・移動をすべて省く。前置きや整理の定型文を付けず、通常の返信だけを1回返す。
- 「続けて」「それで実装して」や承認待ちへの回答など、短くても作業や状態変化を求める依頼は省略対象にしない。
- 提示されている利用可能ツールに必要な一覧・改名・セクション移動が揃っていない場合は整理を省く。整理ツールを探すためだけに追加のexec・検索・環境変数取得・list_threadsを実行しない。明示的な整理依頼の場合だけ、未対応を短く伝える。

## 対象と境界

- Codexデスクトップで、ユーザーと直接話すメインエージェントだけが実行する。サブエージェントから親チャットを変更しない。
- 現在のチャットIDは、実行環境の `CODEX_THREAD_ID` または信頼できる現在チャットのメタデータから取得する。`list_threads` の先頭やタイトルの一致だけで推測しない。
- 現在チャットIDを特定できない場合、またはツールが利用できない場合は操作しない。通常の返信には「振り分け未反映」などの定型追記をしない。アプリDBを直接編集しない。
- 他のチャットを巡回・改名・移動・送信しない。アーカイブや削除もしない。
- 司令塔・固定チャットのピン留めと配置は保持する。自動実行の履歴は「🗃 定期実行の履歴」を保持し、通常のユーザーチャットと混ぜない。いずれも既存の専用タイトルは保持する。

## 判断

まず会話の依頼、実施結果、残作業、必要な次の行動を確認する。ツール呼び出し直前の「作業中」表示だけでは判定しない。回答が終わったことと、タスクが完了したことを区別する。

次の順に、今のボトルネックから1つ選ぶ。

| 状態 | セクション | タイトルの例 |
|---|---|---|
| ユーザーの具体的な確認、選択、承認、回答が必要 | 🔴 確認・判断が必要 | ui-vault-mcp - 部品案を選ぶ |
| 別タスク、CI、外部サービス、別エージェントなどの結果待ち | ⏳ 前提・外部待ち | dom-to-pptx - CI結果を待つ |
| 未完了で次の作業が具体的、前提がそろっている | 🟢 次に着手できる | ui-vault-mcp - 部品選択を実装する |
| 完了・明示的な保留・相談の回答だけで終了 | 📦 あとで・過去 | Codex - 終了時の自動整理を設定済み |
| 次の行動や状態の根拠が足りない | ❔ 状態の確認が必要 | ui-vault-mcp - 残作業を確認する |

単に成果を報告しただけで「確認・判断が必要」にはしない。完了した作業に存在しない次の作業を作らない。実行が必要な残作業を、整理のために中断しない。ユーザーの明示的保留は外部待ちと区別する。

## 名前と反映

1. `list_threads` で現在チャットの実在、タイトル、固定状態、セクションIDと所属を確認する。一覧に出ない場合は公式ツールによる当該IDの読み取りを使い、対象を検証できなければ操作しない。
2. 名前は `プロジェクト名 - 次にすること`。プロジェクトは実際の依頼・リポジトリから判断し、作業用ディレクトリ名から推測しない。プロジェクトなしのCodex設定なら `Codex`、一般相談なら短い主題名を使う。接頭辞の `【】` は使わない。日本語の短い動詞句で、完了した場合は「設定済み」等の結果を使う。GitHub Issue/PRの既存命名規則は変更しない。
3. `set_thread_title` と `move_thread_to_sidebar_section` を使う。改名には現在IDを明示する。既存タイトル・配置が同じなら該当の書き込みを省略する。ツールの名前は提示されている環境の名前空間に合わせる。
4. セクションは名前から最新IDを取得し、固定IDを埋め込まない。同名が複数あり一意に判断できない場合は操作せず報告する。対象セクションがない場合は `create_sidebar_section` で上表の必要な1つだけ作る。
5. 変更後に `list_threads` を読み戻し、現在IDのタイトルとセクション所属を確認する。失敗時は同じ操作を無限に繰り返さず、反映できた部分と未反映を短く報告する。
6. 整理結果は、ユーザーが明示的に求めた場合または整理自体が依頼の場合だけ報告する。通常の返答には整理先・未反映の定型文を付けない。

## 共通指示への設定

[global-instructions.md](references/global-instructions.md) のブロックを `~/.codex/AGENTS.md` に追加する。既存の指示を上書きしない。

これは指示によるターン終了時の処理であり、OSやアプリのイベントフックではない。強制終了・中断・ツール非対応環境では実行されない。既に進行中の他チャットが共通指示を再読込したかは保証できない。新しいチャットからの運用を基本とする。

ルール変更時は [validation-cases.md](references/validation-cases.md) のケースを確認する。
