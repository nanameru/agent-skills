# Codexの共通指示

Gitリポジトリでのコーディング・開発・リファクタリング・バグ修正にはGitHub Issue駆動を適用する。「調査だけ」「短い回答だけ」「コード変更なし」と明示された依頼は対象外。

## 常に守ること

- GitHubを作業記録の正本にし、意味のある判断・発見・検証を関連Issueへ残す。編集前にgit status・remote・ブランチを確認し、実装前にIssueを作成または特定する。無関係な変更を含めない。
- 実際のファイル変更はIssue参照付きでコミットし、remoteがあればpushする。一定以上の作業はDraft PRにまとめる。検証を実行するか、実行できない理由を記録する。secretをコミットしない。
- Issue/PR/Projectなどのタスク名は `【repo名】日本語タイトル`。本文・作業ログも日本語。技術識別子は英語のままでよい。書込不能時は `.codex/issue-knowledge/` に記録して未反映を伝える。
- iOSのxcodebuild・Simulator起動・スクリーンショット撮影はローカルで行わず、DevinのmacOS環境へ任せる。
- ChromeはPlaywright Extensionのタスク別タブグループを使う。OS全体のComputer Useで既存Chromeを前面操作しない。接続で前面化する場合は事前に伝えて元のアプリへ戻す。
- 容量不足時の自動整理は、本人が継続許可した再取得可能キャッシュと非実行中の再生成可能な一時ビルド出力だけ。コード・元資料・成果物・アプリ/ブラウザデータ・認証情報・Trashは対象外。実行前に詳細の許可範囲を読む。

## 必要な場面で読む詳細

詳細は `~/.codex/agent-guides/` にある。次の条件に該当するファイルを行動前に読み、その指示を守る。同じチャットで同じ版を読んでいれば再読しない。参照が見つからない場合は推測せず報告する。

- リポジトリのコード・設定を変更する前: `github-workflow.md`（Issue、ブランチ、コミット、PR、CI、横断Project）。ボード: https://github.com/users/nanameru/projects/3/views/3
- Issue作業の着手・工程変更・終了時: `progress.md`。実際に完了した工程数でAI Companyへ記録する。進捗記録を公開・削除・権限変更などの承認と扱わない。
- Issueの作成/更新、テスト計画/影響範囲の管理時: `test-board.md`。正本はtest-board.yaml。共有YAML/GitHubを変更する前に一言伝える。
- iOSの実装・検証時: `ios.md`。
- ChromeのWeb操作前: `chrome.md`。
- 容量不足でキャッシュ整理が必要な時: `cache-cleanup.md`。
- 実作業後の最終回答前、信頼できる現在チャットIDと必要な整理ツールが利用できる時だけ: `chat-wrapup.md` とその参照スキル。挨拶だけ、ツール不足、他チャットには適用しない。

## 軽い作業の負担を増やさない

- 関連Issue・必要な検証・安全制約を維持し、同じ判断や結果の記録は工程単位でまとめる。キーストロークやツール呼び出しごとの進捗記録はしない。
- 可逆的で影響の小さい設定・文書変更は、変更箇所に合う手動検証や構文確認を使い、無関係なアプリのビルドや実装をなぞるだけのテストを追加しない。何を確認したかIssueへ記録する。
- ファイルやツールを探す時は名前・該当箇所から絞り込み、一覧・説明・ログの全文を不用意に出力しない。結果が欠けて判断できない時は原文を取得する。
