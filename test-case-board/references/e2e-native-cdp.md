# Native CDP runner（明示選択）

`test-board e2e` に `--provider native-cdp --url http://127.0.0.1:PORT/ --chrome /absolute/path/to/chrome` を加える。`--browser` は agent-browser 0.43.0 の実行ファイル、`--data-kind fixture` は必須。URL は localhost / 127.0.0.1 / ::1 に限定する。URL の fixture server は呼び出し側が用意する。各試行の private UUID ディレクトリに専用 profile、空 config、socket と session を作る。

runner は `contractVersion = 'test-board-native-cdp-v1'` と `async run({ caseId, step, cdp, page })` を export する。`await step('name', async () => { ... })` の中で `await cdp.send(method, params, page.sessionId, timeoutMs)`、`await page.evaluate(expression, opts)`、`await page.evalValue(expression, opts)` を使う。`cdp.on(method, handler)` は解除関数を返す。event handler は `(params, sessionId)`、`'*'` は `(method, params, sessionId)` を受ける。`page.sleep(ms)` と `page.waitFor(expression, options)` も利用できる。元テストの所有確認用 `cdp.send('Target.getTargets')` は browser 読取だけを許可する。step と送信は逐次 await し、並行・未 await・step 外の操作を行わない。Target の作成・変更、Browser method、session 切替は公開しない。これは信頼済み runner の契約であり JavaScript sandbox ではない。入力と assertion・待機・速度は元テストに合わせる。

遷移は明示 opt-in: `--allow-url http://127.0.0.1:PORT/path --allow-url 'http://127.0.0.1:PORT/path?theme=dark'` のように URL を最大100回指定し、step 内で `await page.navigate('http://127.0.0.1:PORT/path')` とする。同じ URL の reload もその URL の宣言が必要。宣言なしは初期 URL の完全一致を維持する。各 URL は絶対 HTTP(S)、初期 URL と同一 origin（host・port を含む）の localhost、credentials・空白・wildcard なしに限る。URL 標準の正規化後の完全一致であり、query・fragment は明示されたものだけ許可する。origin 全体の許可や期待 URL の setter はない。`Page.navigate`、`Page.reload`、`Page.navigateToHistoryEntry` の直接送信は禁止。遷移要求前の所有確認、同一 session の `Page.navigate` と commit event、遷移後の URL・所有確認がすべて成功したときだけ期待 URL を更新する。失敗は更新しない。要求・観測 URL、step、成否とエラーは private result の step 内 `navigations` と log に残る。宣言外などの失敗を runner が捕捉しても実行は失敗する。

録画前に fixture を open して正式 `get cdp-url` の loopback browser endpoint を取得し、単一 page の初期観測後に所有 session を attach する。その session を含む観測を record start の前後で行い、成功後に worker へ解放する。各観測は正式 endpoint の再取得、CLI tab、CDP の全 target/context 集合と所有 session 上の `Target.getTargetInfo` を照合し、生観測を private log に同期保存する。各 step と遷移の前後で再検査し、個々の入力間に CLI を挟まない。session probe は読取だが CDP コマンドを追加する。遷移時の `Page.enable` は session の Page event を有効にし、runner もそれらを受け取る。CDP method・params・送信時刻は private log に残る。endpoint や生ログは公開しない。標準 stop、全 decode・実 PTS・hash、worker の実 exit/signal、result-v1 と中断の分離は共通入口を使う。capture 内部 target や画面内容の目視は自動合格にならない。実行ごとの原本を保持し、retry は新しい試行にする。

`result.test.nativeCdpOperations` は runner 操作と navigation の送信を試みた CDP 操作数（内部 probe は除外）、`nativeInputOperations` は `Input.dispatchTouchEvent`・`Input.dispatchKeyEvent`・`Input.dispatchMouseEvent` の成功応答数。遷移用の `Page.enable` は内部初期化として個別の CDP log・この計数の対象外。後者が 0 の実行は成功にならず、`result.error` に理由を残す。進行中の CDP 応答待ちで中断後の録画停止が遅れる場合があり、全処理の厳密な deadline は保証しない。runner が CDP error を catch しても契約エラーとして失敗にするため、元テストとの互換は未検証。所有検査は離散観測であり、観測間に開閉された page や、JavaScript 等による一時的な URL 変更をすべて検出できない。直接遷移は期待 URL を更新せず、境界で不一致なら失敗する。fixture でも別 page の作成・直接遷移は禁止で、信頼済み runner を前提とし sandbox ではない。session probe の成功は録画内部の target を証明しない。

所有 page と endpoint・browser・context・所有 session は固定する。`Target.getTargets` の各 `iframe` は、公式 `TargetInfo.parentId` をたどり、途中を iframe のみとして固定 page に到達し、page と全段に明示された `browserContextId` が一致するときだけ、再生成可能な所有子 iframe と分類する。いずれかの ID の欠落、親不明、循環、異なる context、途中の別種 target は証明不能として停止する。URL や opener は iframe 帰属の証拠にしない。

起動時 `initial-target` の成功時だけ固定する集合について、以下の組合せで確認した拡張 service worker の**消失のみ**を許す。browser が列挙した `type=service_worker`、正規の `chrome-extension://` script URL（32文字の a〜p の拡張 ID、空でない path、query/fragment なし）、所有 page と一致する明示 `browserContextId` を要求し、同じ observer で正式 `Target.getTargetInfo(targetId)` を追加取得して ID・type・URL・context と親/opener等の由来属性を列挙結果と照合する。runner の自己申告 URL は使わない。title・attached は変動する運用属性であり照合対象に含めない。公式情報の取得失敗・不一致では停止し、default context の明示 ID がない場合や候補条件を満たさない worker には例外を適用しない。それらは固定集合に残り、消失すれば停止する。

確認済み worker は、観測される間は上記の由来属性を固定する。消失を一度観測した ID の再出現、別 ID での再生成、新規 worker、他の未知 target、新 page、所有 page の交換や帰属不明 iframe は拒否する。worker は iframe の子として扱わず、消失を page 不変の証明にもしない。分類・正式照合・baseline・残存・許可消失・拒否理由を phase・step とともに既存 private log に保存する。観測間に消失・再出現した場合は識別できない。

[CDP TargetInfo と getTargetInfo](https://chromedevtools.github.io/devtools-protocol/tot/Target/#type-TargetInfo) は browser の target 情報を返すが、context は optional / experimental。[Chromium の service worker 実装](https://chromium.googlesource.com/chromium/src/+/lkgr/content/browser/devtools/service_worker_devtools_agent_host.cc) は type と script URL を返し、[Chrome の拡張仕様](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/basics) は拡張 package 内の背景 script を登録する。[Chromium の ID 定義](https://chromium.googlesource.com/chromium/chromium/+/trunk/extensions/common/extension.h) は32文字の a〜p を指定する。これらの正式情報と一致条件から拡張由来と分類する推論であり、拡張登録簿の独立照合ではない。実 Chrome で必要な情報・API が得られるかは別途検証が必要。
